# Deployment

Frontend: Vercel project `jaydeo-trav-planner`, root directory `frontend`. Build and output settings are in `frontend/vercel.json`. Set `API_BASE_URL` to the Render HTTPS URL followed by `/api/v1`. Flutter 3.47.2 is pinned.

Backend: import `render.yaml` as a Render Blueprint. The free Python web service deploys from `main`. Use an external Neon Free PostgreSQL project and supply its connection URL as the Render DATABASE_URL secret. Migrations run before the API starts; `/health` checks PostgreSQL. JWT signing secrets are generated by Render.

Automatic updates: push to `main`; Vercel and Render GitHub integrations build and deploy. GitHub Actions runs frontend checks and focused production configuration tests. Existing legacy AI tests currently fail collection and are not part of that check.

AI: add `GEMINI_API_KEY` and optionally `GROQ_API_KEY` in the Render service environment. Never commit secrets. Set `ALLOWED_ORIGINS` to the exact frontend domain if the Vercel domain changes.

Use Neon Free instead of Render free PostgreSQL to avoid Render’s 30-day database expiry. Neon usage quotas still apply. Free web instances can sleep while idle. New production database starts empty; local accounts and travel records are not copied automatically.
